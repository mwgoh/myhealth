## 1. 목적과 범위

### 사용자와 사용 상황

- 사용자 한 명이 휴대폰 한 대에서 사용한다. 로그인과 동기화는 없다.
- 헬스장에서 세트를 끝낼 때마다 바로 입력하는 것이 주된 사용 방식이다.
- 운동은 다섯 가지로 분류해 기록한다: #근력운동, #맨몸운동, #코어운동, #스트레칭, #유산소
- 기록은 날짜별 목록, 월 달력, 주간·월간 요약으로 본다.

### 성공 기준

1. 직전 세트와 같은 값의 세트는 `세트 추가` 한 번으로 입력된다.
2. 입력 직후 화면을 끄거나 새로고침해도 완성된 세트는 남아 있다.
3. 한국 시간 새벽(0~9시)에 입력한 기록도 달력과 요약에서 입력한 날짜에 표시된다.
4. JSON으로 내보낸 뒤 다시 가져오면 데이터가 그대로 복원된다.
5. 저장된 데이터가 손상되어도 앱이 그 데이터를 덮어쓰지 않는다.
6. `next build`가 정적 사이트 생성까지 통과한다.

### 이번 범위

- 기능 전체를 만들고, PC의 localhost를 휴대폰 크기 화면으로 열어 동작을 확인하는 데까지 한다.
- 코드는 나중에 정적 사이트로 배포할 수 있는 구조로 만든다.

### 이번에 하지 않는 것

- PWA(홈 화면 추가, 서비스 워커), `navigator.storage.persist()` 요청, 배포
- 그래프(종목별 추이)
- 기기 간 동기화, 로그인
- lb 단위, 어시스트(음수) 중량
- 종목 이름 변경, 세트 순서 변경
- 한 종목에 여러 분류 붙이기
- 직접 추가한 종목의 가이드 작성
- UI 컴포넌트 자동 테스트

## 2. 알려진 위험: 데이터 유실

| 위험 | 내용 | 대응 |
|---|---|---|
| iOS Safari 저장소 삭제 | 7일 동안 사이트를 열지 않으면 localStorage를 지울 수 있다 | 이번: JSON 백업. 배포 단계: PWA로 홈 화면 추가 |
| 접속 주소(origin) 변경 | localStorage는 주소마다 따로 저장되어, IP로 접속하면 IP가 바뀔 때 기록이 보이지 않는다 | 배포 단계: 고정 HTTPS 주소 사용 |
| 기기 분실·교체 | 복구할 방법이 없다 | JSON 백업 |

JSON 내보내기·가져오기는 선택 기능이 아니라 필수 기능이다.

## 3. 기술 스택

- Next.js 16.4 (App Router, TypeScript, `output: 'export'`)
- React 19
- Tailwind CSS 4
- zod 4: 저장 데이터와 가져온 파일을 검증한다.
- Vitest 5: 단위 테스트를 한다.
- 상태 관리 라이브러리는 쓰지 않고, `useSyncExternalStore`로 저장소를 구독한다.
- 글꼴은 시스템 기본 글꼴을 쓴다(외부 요청 없음).
- 패키지 관리자는 npm이다.

## 4. 데이터 모델

```ts
// 측정 방식: 어떤 칸에 무엇을 입력하는가
type MeasureKind = 'weighted' | 'reps' | 'timed' | 'cardio'
//                  무게×횟수    횟수(+추가 중량)  시간(초)  시간(분)·거리

// 분류: 화면에 해시태그로 보여준다
type Category = 'strength' | 'bodyweight' | 'core' | 'stretching' | 'cardio'
//               #근력운동    #맨몸운동      #코어운동  #스트레칭    #유산소

type Exercise = {
  id: string
  name: string
  kind: MeasureKind
  category: Category
  archived: boolean          // 숨김. 기본 종목과 기록에 쓰인 종목은 삭제 대신 숨긴다
}

type Entry =
  | { id: string; exerciseId: string; kind: 'weighted'; sets: { weightKg: number; reps: number }[] }
  | { id: string; exerciseId: string; kind: 'reps';     sets: { reps: number; addedKg: number }[] }
  | { id: string; exerciseId: string; kind: 'timed';    sets: { seconds: number }[] }
  | { id: string; exerciseId: string; kind: 'cardio';   durationMin: number; distanceKm?: number }

type Workout = {
  id: string
  date: string               // "YYYY-MM-DD", 현지 날짜
  createdAt: string          // ISO 타임스탬프, 같은 날짜의 기록을 정렬할 때만 사용
  startTime?: string         // 운동 시작 시간 "HH:MM" (선택, 2026-11-10 추가)
  endTime?: string           // 운동 종료 시간 "HH:MM" (선택, 2026-11-10 추가)
  durationMin?: number       // 그날 총 운동 시간. 시작·종료가 모두 있으면 그 차이로 저장하고, 아니면 직접 입력 (선택)
  memo?: string
  entries: Entry[]           // 저장된 기록은 항상 1개 이상
}

type Store = { version: 1; exercises: Exercise[]; workouts: Workout[] }
```

### 규칙

- **측정 방식과 분류는 서로 독립이다.**
  - 예: 플랭크는 `timed` + `core`, 크런치는 `reps` + `core`, 햄스트링 스트레칭은 `timed` + `stretching`
  - 직접 종목을 추가할 때 분류를 고르면 측정 방식의 기본값을 채워준다.
    - `strength` → `weighted`
    - `bodyweight`, `core` → `reps`
    - `stretching` → `timed`
    - `cardio` → `cardio`
  - 채워준 측정 방식은 바꿀 수 있다.
- **기록과 종목의 측정 방식 일치**: `Entry.kind`는 참조하는 `Exercise.kind`와 같아야 한다.
- **좌우 동작 기록 방법** (가이드에도 적는다)
  - 좌우를 번갈아 하는 동작(런지, 데드버그, 버드독, 러시안 트위스트, 마운틴 클라이머)은 좌우 합계 횟수를 적는다.
  - 한쪽씩 따로 하는 동작(사이드 플랭크, 한쪽 스트레칭)은 한쪽을 한 세트로 적는다.
- **날짜**
  - `"YYYY-MM-DD"` 문자열로 저장한다.
  - 문자열을 `Date`로 바꿀 때는 `new Date(y, m - 1, d)`로 현지 시간을 쓴다.
  - `new Date("2026-11-09")`는 UTC로 해석되므로 쓰지 않는다.
- **주의 시작**: 월요일이다.
- **종목 이름 중복**
  - 앞뒤 공백을 제거하고 대소문자를 구분하지 않고 비교해, 같은 이름의 종목은 추가할 수 없다.
  - 같은 이름이 숨김 상태라면 숨김 해제를 안내한다.
- **하루 기록 개수**: 하루에 여러 기록을 만들 수 있다. '운동 일수'는 고유 날짜 수로 센다.
- **ID 생성**: `crypto.randomUUID()`를 쓴다. 없는 환경(HTTPS나 localhost가 아닌 주소)에서는 대체 생성 함수를 쓴다.
- **기본 종목**: 고정 ID(예: `seed-bench-press`)를 쓴다.

### 입력값 범위

| 필드 | 범위 |
|---|---|
| `weightKg` | 0 이상 1000 이하, 소수 허용 |
| `reps` | 정수, 1 이상 1000 이하 |
| `addedKg` | 0 이상 500 이하, 소수 허용. 비워 두면 0 |
| `seconds` | 정수, 1 이상 36000 이하 |
| 유산소 `durationMin` | 0 초과 1440 이하, 소수 허용 |
| `distanceKm` | 0 초과 1000 이하, 소수 허용, 선택 |
| 기록 `durationMin` | 정수, 1 이상 1440 이하, 선택 |
| `memo` | 1000자 이하 |
| `startTime`, `endTime` | 24시간 `HH:MM`. 종료가 시작보다 이르면 자정을 넘긴 것으로 본다. 차이가 0분이면 총 운동 시간을 계산하지 않는다 |
| `date` | 실제로 존재하는 날짜 |

## 5. 기본 종목과 가이드

### 가이드 저장 방식

- 가이드 문구는 `Store`에 저장하지 않고 앱 코드(`seed.ts`)에 기본 종목 ID별로 둔다.
  - 문구를 고쳐도 사용자 데이터를 바꿀 필요가 없다.
  - 백업 파일이 커지지 않는다.
- 직접 추가한 종목에는 가이드가 없다.
- 가이드의 공통 안내: "반동 없이 천천히, 통증이 느껴지면 멈추세요."

| seed-running | 러닝 | 심폐·하체 | 대화가 가능한 강도를 기본으로 한다 |
| seed-walking | 걷기 | 심폐 | 팔을 자연스럽게 흔들며 빠른 걸음으로 걷는다 |
| seed-cycling | 사이클 | 심폐·허벅지 | 페달이 가장 아래일 때 무릎이 살짝 굽는 안장 높이 |
| seed-rowing | 로잉 | 심폐·등·하체 | 다리 → 허리 → 팔 순서로 당긴다 |
| seed-swimming | 수영 | 심폐·전신 | 거리는 km로 적는다 (1500m → 1.5) |
| seed-jump-rope | 줄넘기 | 심폐·종아리 | 앞꿈치로 낮게 뛴다 |

## 6. 요약 계산

**기간**
- 주: 월요일부터 일요일까지(현지 날짜)
- 월: 1일부터 말일까지

| 지표 | 계산 |
|---|---|
| 운동 일수 | 기간 안에 기록이 있는 고유 날짜 수 |
| 분류별 운동 일수 | 분류마다, 그 분류의 종목이 하나라도 있는 고유 날짜 수 (예: #스트레칭 5일) |
| 총 운동 시간(분) | 기록마다 `durationMin`이 있으면 그 값, 없으면 그 기록의 유산소 `durationMin` 합을 더한다 |
| 총 볼륨(kg) | `weighted` 세트의 `weightKg × reps` 합 + `reps` 세트의 `reps × addedKg` 합(2026-11-10). 맨몸 무게는 몸무게를 모르므로 넣지 않는다 |
| 총 횟수 | `reps` 세트의 `reps` 합. `addedKg`는 반영하지 않는다 |
| 유산소 총 시간(분) | `cardio` 기록의 `durationMin` 합 |
| 유산소 총 거리(km) | `cardio` 기록의 `distanceKm` 합 |

- `timed`(시간) 세트는 운동 일수와 분류별 운동 일수에만 반영한다.
- 스트레칭만 한 날도 운동 일수에 들어간다.
- 분류별 운동 일수는 숨긴 종목도 포함해 센다. 기록에 남은 종목의 분류를 기준으로 한다.
- `durationMin`이 없고 유산소 종목도 없는 기록은 총 운동 시간에 0으로 들어간다.
  - 이런 기록이 1개 이상이면 "운동 시간이 입력되지 않은 기록 N개"를 함께 보여준다.
- 화면에 표시할 때 반올림한다.
  - 볼륨과 횟수는 정수에 천 단위 쉼표를 붙인다.
  - 거리는 소수 첫째 자리까지 보여준다.
  - 시간은 60분 이상이면 "1시간 30분" 형식으로 보여준다.

## 7. 화면

### 공통

- 휴대폰 화면을 우선으로 설계하고, 터치 영역은 44px 이상으로 한다.
- 다크 모드는 기기 설정(`prefers-color-scheme`)을 따른다.
- UI는 한국어로 쓴다.
- 분류는 해시태그 모양의 작은 칩으로 보여준다(예: `#코어운동`).
- 탭 화면 네 곳 아래에 하단 탭(기록, 달력, 요약, 설정)을 둔다.
- 탭 화면 네 곳에 떠 있는 `+ 운동 기록` 버튼을 둔다. 이 버튼은 오늘 날짜로 새 기록을 연다.
- 숫자 입력 칸은 `inputMode="decimal"`(소수 허용 칸) 또는 `"numeric"`(정수 칸)을 쓴다.
- 삭제할 때는 직접 만든 확인 창을 쓴다(브라우저 기본 `confirm`은 쓰지 않는다).

### `/` 기록 (홈)

- 맨 위에 이번 주 요약 카드를 둔다. 운동 일수, 총 운동 시간, 총 볼륨을 보여준다.
- 그 아래에 기록 목록을 둔다.
  - 정렬: 날짜 내림차순, 같은 날짜는 `createdAt` 내림차순
  - 월마다 구분 머리글을 붙인다.
- 카드에는 다음을 보여준다.
  - 날짜와 요일
  - 그날 한 분류의 해시태그
  - 종목별 짧은 요약(예: "벤치프레스 5세트 · 플랭크 3세트 · 러닝 30분")
- 카드를 누르면 편집 화면으로 간다.
- 기록이 없으면 "아직 기록이 없습니다"와 기록 추가 버튼을 보여준다.

### `/calendar` 달력

- 월요일부터 시작하는 월 달력이다.
  - 운동한 날에는 그날 한 분류마다 분류 색 점을 표시하고(최대 5개, 모두 보인다), 오늘을 강조한다.
  - ◀ ▶로 월을 이동한다.
- 날짜를 누르면 그날의 기록 카드 목록과 `이 날짜로 기록 추가` 버튼이 나온다.
- 선택한 날짜는 주소(`/calendar?date=YYYY-MM-DD`)에 반영한다. 편집 화면에서 돌아와도 같은 달과 날짜가 유지된다.

### `/stats` 요약

- 주간과 월간을 전환하고, ◀ ▶로 기간을 이동한다.
- 현재 기간보다 미래로는 이동할 수 없다.
- 기간 이름(예: "11월 9일 – 11월 15일", "2026년 11월")과 6절의 지표 전체를 보여준다.
- 분류별 운동 일수는 다섯 분류를 모두 나열한다. 0일인 분류도 보여준다.

### `/settings` 설정

- **종목 관리**
  - 분류별로 묶어서 보여준다.
  - 추가할 때는 이름, 분류, 측정 방식을 입력한다. 분류를 고르면 측정 방식의 기본값이 채워진다.
  - 숨김과 숨김 해제를 할 수 있다.
  - 가이드가 있는 종목은 이름을 누르면 따라하기 영상과 주요 부위·핵심 포인트가 펼쳐진다. 한 번에 하나만 펼친다.
  - 직접 추가한 종목은 삭제할 수 있다(확인 창 필요).
    - 기록에 쓰인 종목은 삭제할 수 없다. 지우면 그 기록이 없는 종목을 가리켜 데이터 전체가 손상으로 판정되기 때문이다.
    - 이때는 쓰인 기록 수를 알리고 숨기기를 권한다. 기본 종목은 숨기기만 된다.
- **백업**
  - 내보내기: `workout-log-backup-YYYY-MM-DD.json` 파일로 내려받는다.
  - 가져오기: 파일을 고르고, 검증과 확인을 거친 뒤 교체한다. 자세한 동작은 9절에 있다.
- **전체 초기화**: 확인 창을 거친 뒤 기본 종목만 있는 상태로 되돌린다.

### `/workout` 편집

**주소**
- `?date=YYYY-MM-DD`: 그 날짜로 새 기록을 만든다. 날짜가 잘못되었으면 오늘로 연다.
- `?id=…`: 기존 기록을 편집한다. 기록이 없으면 "기록을 찾을 수 없습니다"와 목록으로 가는 링크를 보여준다.
- 둘 다 없으면 오늘 날짜로 새 기록을 연다.
- 새 기록이 처음 저장되는 순간 `router.replace`로 주소를 `?id=…`로 바꾼다. 새로고침해도 기록이 중복으로 생기지 않는다.

**머리글**
- 뒤로 가기 버튼을 둔다.
- 저장 상태를 표시한다.
  - 저장 중
  - 저장됨
  - 저장 실패
  - 완성된 종목이 없어 저장되지 않음
- 기존 기록이면 삭제 버튼을 둔다.

**본문**
- 날짜(`type="date"`), 총 운동 시간(분, 선택), 시작·종료 시간(`type="time"`, 선택), 메모(선택)
  - 시작·종료 칸 옆의 `지금` 버튼은 현재 시각을 넣는다. 헬스장에서 시작할 때와 끝날 때 한 번씩 누른다.
  - 시작·종료가 모두 있으면 총 운동 시간은 자동 계산해 보여주고 직접 입력할 수 없다. 아니면 직접 입력한다(예전 기록 호환).
  - 시작 시간을 자동으로 채우지 않는다. 운동을 마친 뒤 기록하면 기록하는 시각이 시작 시간으로 잘못 들어가기 때문이다.
- 기록 카드에는 운동 시간 줄을 보여준다(예: `07:10–08:25 · 1시간 15분`, 시간 없이 총 시간만 있으면 `45분`).
- 종목 카드
  - 종목 이름과 분류 칩을 보여준다.
  - 가이드가 있는 종목은 ⓘ 버튼을 누르면 따라하기 영상과 주요 부위·핵심 포인트가 펼쳐진다.
  - 종목 선택 창에서 방금 고른 종목(여러 개면 첫 번째)은 가이드를 펼친 채 추가되고, 그 카드가 보이게 스크롤한다. 저장된 기록을 열 때는 닫혀 있다.
  - 종목 삭제 버튼을 둔다. 완성된 세트가 있는 종목은 삭제할 때 확인 창을 띄운다.
- 측정 방식별 입력 줄
  - `weighted`: `[무게 kg] [횟수] [×]`
  - `reps`: `[횟수] [+kg] [×]`. `+kg`는 작게 보여준다.
  - `timed`: `[초] [×]`
  - `cardio`: `[시간 분] [거리 km]`. 세트 없이 한 줄이다.
- `세트 추가`는 직전 세트의 입력값을 복사한다. 첫 세트는 빈 칸이다.

**종목 선택 창**
- 아래에서 올라오는 창이다.
- 맨 위에 분류 필터 칩을 둔다: `전체` `#근력운동` `#맨몸운동` `#코어운동` `#스트레칭` `#유산소`
  - 3열 2줄로 6개가 모두 보이게 한다(가로 스크롤이면 뒤쪽 분류가 화면 밖에 숨는다).
- 여러 종목을 한 번에 고른다(2026-11-10).
  - 줄을 누르면 고르기/풀기가 바뀌고, 고른 순서가 번호로 보인다. 분류를 바꾸거나 검색해도 고른 것은 유지된다.
  - 아래쪽 `N개 종목 추가` 버튼으로 고른 순서대로 한꺼번에 추가한다. 닫으면 고른 것을 버린다.
  - 이 기록에 이미 있는 종목은 `추가됨`으로 보여주고 고를 수 없다(같은 종목을 두 번 넣지 않는다). 카드를 지우면 다시 고를 수 있다.
  - 추가한 종목 중 첫 번째 카드만 가이드를 펼치고 그 카드로 스크롤한다(영상이 동시에 여러 개 재생되지 않게).
- 가이드가 있는 종목은 오른쪽 ▶ 버튼으로 그 줄 아래에 따라하기 영상을 펼친다.
- 검색할 수 있다. 검색은 선택한 분류 안에서만 한다.
- 최근 사용순으로 정렬한다. 가장 최근 기록에 쓰인 종목이 앞에 오고, 쓰지 않은 종목은 기본 순서대로 뒤에 둔다.
- 종목 이름 아래에 주요 부위를 작게 보여준다. 가이드가 있는 종목만 해당한다.
- 숨긴 종목은 보이지 않는다.
- 검색 결과가 없으면 "'검색어' 새 종목으로 추가"를 보여준다.
  - 분류와 측정 방식을 고를 수 있다.
  - 선택 중인 분류 필터를 기본값으로 쓴다. `전체`일 때는 #근력운동을 기본값으로 쓴다.
  - 만든 종목은 고른 목록에 들어가고 검색어가 지워져, 다른 종목도 이어서 고를 수 있다.

```

    types.ts       타입, zod 스키마, 참조 무결성 검사, 분류·측정 방식 라벨

    workout.ts     편집 초안 ↔ 저장 형식 변환, 세트 복사, 완성 판정
    seed.ts        기본 종목, 가이드 문구, 초기 Store
    id.ts          ID 생성 (대체 함수 포함)
  storage/
    store.ts       불러오기·저장·구독, 상태 관리

  components/    BottomNav, FloatingAddButton, WorkoutCard, EntryCard, SetRow,

  hooks/

```

- 페이지는 모두 클라이언트 컴포넌트다.
- `useSearchParams`를 쓰는 페이지는 `Suspense`로 감싼다. 정적 사이트로 내보낼 때 필요하다.

### 편집 초안

- 편집 화면은 입력값을 문자열 그대로 담은 초안(draft)을 상태로 가진다.
- `workout.ts`의 `toPersistable(draft): Workout | null`이 초안을 저장 형식으로 바꾼다.
  - 완성되지 않은 세트는 뺀다.
    - `weighted`: 무게나 횟수가 비었거나 범위를 벗어난 세트
    - `reps`: 횟수가 비었거나 범위를 벗어난 세트
    - `timed`: 초가 비었거나 범위를 벗어난 세트
  - 완성된 세트가 0개인 종목과, 시간이 없는 유산소 종목은 뺀다.
  - 남은 종목이 0개면 `null`을 돌려준다.
- `null`일 때의 처리
  - 새 기록이면 아무것도 저장하지 않는다.
  - 기존 기록이면 마지막으로 저장된 내용을 그대로 둔다. 머리글에 "완성된 종목이 없어 저장되지 않음"을 표시한다.
  - 기록을 지우려면 삭제 버튼을 쓴다.
- 미완성 세트는 화면에만 남고, 앱을 다시 열면 사라진다.

### 자동 저장 (`useAutosave`)

- 초안이 바뀌면 500ms 뒤에 `toPersistable` 결과를 저장한다.
- 다음 경우에는 기다리던 저장을 즉시 실행한다.
  - `visibilitychange`(hidden)
  - `pagehide`
  - 편집 화면을 벗어날 때(컴포넌트 언마운트)

### 저장소 (`store.ts`)

- localStorage 키 `workout-log` 하나에 `Store` 전체를 JSON으로 저장한다.
- 테스트할 수 있도록 `getItem`과 `setItem`만 가진 저장 객체를 주입받는다. 테스트에서는 메모리 구현을 넣는다.
- **상태**
  - `loading`: 서버 렌더링 중이거나 아직 읽기 전
  - `ready`
  - `corrupt`: JSON을 읽지 못했거나 스키마 검증에 실패함. 원본 문자열을 보관한다
  - `unsupported-version`: `version > 1`
- **불러오기**
  - 키가 없으면 기본 Store를 만들어 저장한다.
  - 그 밖에는 검증 결과에 따라 상태를 정한다.
- **화면 불일치(hydration) 방지**: `getServerSnapshot`은 `loading`을 돌려준다. `loading`인 동안은 로딩 화면만 그린다.
- **쓰기**
  - `ready`일 때만 쓴다. `corrupt`이거나 `unsupported-version`이면 쓰지 않아 원본을 보존한다.
  - `setItem`이 예외를 던지면 저장 실패 이벤트를 알리고, 메모리의 상태는 유지한다.
- **다른 탭**: 다른 탭이 바꾼 내용은 `storage` 이벤트를 받아 다시 불러온다. 두 탭에서 동시에 수정하면 나중에 저장한 쪽이 남는다. 이 한계는 받아들인다.
- **API**: `upsertWorkout`, `deleteWorkout`, `addExercise`, `setExerciseArchived`, `replaceAll`, `resetAll`

## 9. 오류 처리

| 상황 | 동작 |
|---|---|
| 저장 데이터 손상 (`corrupt`) | 오류 화면에 '원본 그대로 내보내기'와 '초기화'(확인 창 필요)만 보여준다. 자동으로 덮어쓰지 않는다 |
| 새 버전 데이터 (`unsupported-version`) | 손상 때와 같은 오류 화면을 보여주되, 안내 문구만 다르다 |
| 저장 실패 (용량 초과, 사생활 보호 모드) | 저장 상태에 "저장 실패"를 표시하고 알림을 띄운다. 입력 내용은 화면에 유지한다 |
| 가져오기: JSON이 아님, 스키마 불일치, 존재하지 않는 종목 참조, 측정 방식 불일치, 지원하지 않는 버전 | 원인을 보여주고 기존 데이터는 건드리지 않는다 |
| 가져오기: 검증 통과 | 확인 창에 "현재 기록 N개를 가져온 기록 M개로 덮어씁니다"를 보여준다. 확인 창 안에 '현재 데이터 먼저 내보내기' 버튼을 둔다. 확인하면 교체한다 |
| 편집: 없는 `id` | "기록을 찾을 수 없습니다"와 목록으로 가는 링크를 보여준다 |
| 입력값 범위 초과 | 그 칸에 빨간 테두리와 안내 문구를 보여준다. 그 세트는 미완성으로 처리한다 |

## 10. 테스트

**단위 테스트 (Vitest)**
- `domain`과 `storage`는 테스트를 먼저 쓴다(TDD).
- `date`
  - 현지 날짜 변환
  - 월요일 기준 주 범위(연말을 넘는 주 포함)
  - 월 달력 칸(월요일 시작, 앞뒤 빈 칸)
- `summary`
  - 빈 기간
  - 하루에 여러 기록이 있는 경우의 운동 일수
  - 분류별 운동 일수(숨긴 종목 포함)
  - 총 운동 시간 대체 규칙과 미입력 기록 개수
  - `reps`와 `timed`의 반영 범위
- `workout`
  - 세트 복사
  - 미완성 세트·종목 제외
  - 빈 초안이면 `null`
  - 범위 검사
- `seed`
  - 기본 종목 ID가 중복되지 않음
  - 모든 기본 종목에 가이드가 있음
  - 초기 Store가 스키마를 통과함
- `store`
  - 첫 실행 시 기본 데이터 생성
  - 손상 데이터일 때 쓰기 차단
  - 버전 불일치
  - `setItem` 예외 처리
- `backup`
  - 내보낸 뒤 가져오면 원래대로 복원
  - 참조 무결성 위반 거부
  - 측정 방식 불일치 거부

**빌드 확인**
- `npm run build`(정적 사이트 생성)가 통과해야 한다.
- `npm run lint`가 통과해야 한다.

**화면 확인 (브라우저, 휴대폰 크기 화면)**
1. 근력, 맨몸, 코어, 스트레칭, 유산소 기록을 하나씩 추가하고 세트 복사가 되는지 본다.
2. 종목 선택 창의 분류 필터, 검색, 가이드(ⓘ)가 동작하는지 본다.
3. 입력 직후 새로고침해도 기록이 유지되는지 본다.
4. 달력 날짜를 선택하고 편집한 뒤 돌아왔을 때 선택이 유지되는지 본다.
5. 주간·월간 요약 숫자를 직접 계산한 값과 비교한다(분류별 운동 일수 포함).
6. 내보내기 → 전체 초기화 → 가져오기로 복원되는지 본다.
7. 개발자 도구에서 localStorage 값을 망가뜨리고 오류 화면이 나오는지 본다.
